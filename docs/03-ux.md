# Diseño UX — Gestión de turnos

> Cada pantalla indica los requisitos (FR) y recorridos (RU) del [PRD](02-prd.md) que cubre.
> Los supuestos nuevos arrancan en **S-26**.

## 1. Principios

1. **Dos aplicaciones en una.** El paciente y el personal tienen necesidades opuestas:
   el paciente va lento, desde el celular y una vez por mes; la recepcionista va rápido,
   con teclado y 80 veces por día. Comparten estilo, pero no pantallas.
2. **Paciente: un paso por pantalla.** Una pregunta, botones grandes, nada de menús.
3. **Recepción: todo en una pantalla.** Buscar, elegir y confirmar sin cambiar de página,
   con teclado (Enter confirma, Esc cancela). Así se cumple el minuto de CE-04.
4. **El error dice qué hacer.** Nunca "Error 409": siempre qué pasó y cuál es el próximo paso.
5. **Confirmar sólo lo irreversible.** Reservar no pide "¿está seguro?" (se puede cancelar).
   Cancelar y bloquear, sí.

## 2. Estilo visual

| Elemento | Decisión |
|---|---|
| Tipografía | Sans serif del sistema. Texto base 16 px en el personal y 18 px en el paciente. |
| Color principal | Azul institucional `#1F5FA8` (botones y encabezados). Contraste ≥ 4,5:1 sobre blanco. |
| Estados de turno | Reservado: azul · Cancelado por el paciente o la recepción: gris · Cancelado por el hospital: naranja `#B45309`. Siempre con texto además del color. |
| Botones del paciente | Alto mínimo 48 px, ancho completo en el celular. |
| Fechas | "Martes 10 de noviembre, 10:30". Nunca `10/11` (se confunde día y mes). |
| Íconos | Planos y siempre acompañados de texto. |

```
 Paso 1 de 4               Paso 2 de 4                Paso 3 de 4                Paso 4 de 4
┌──────────────────────┐  ┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐

│ [ Pediatría        ] │  │ [ libre, con       ] │   │ │14:00││14:30││15:00││   │ Cardiología          │
│ [ Traumatología    ] │  │ [ cualquier médico ] │   │ └─────┘└─────┘└─────┘│   │ Dr. Diego Fernández  │
│                      │  │                      │   │                      │   │                      │
│                      │  │ [ Dr. Diego        ] │   │ Viernes 13 de nov.   │   │ Llegá 15 minutos     │
│                      │  │ [ Fernández        ] │   │ ┌─────┐┌─────┐       │   │ antes con tu DNI.    │

│                      │  │ [ Próximo: jue 12  ] │   │                      │   │ └──────────────────┘ │
└──────────────────────┘  └──────────────────────┘   └──────────────────────┘   └──────────────────────┘
```

- Paso 2 lista los médicos de la especialidad con su próximo día libre, para que el paciente
  compare. La primera opción, **El primer turno libre, con cualquier médico**, sirve a quien no
  tiene preferencia. Un médico sin horarios libres en los próximos 60 días aparece gris con
  "Sin turnos disponibles".
- Paso 3 agrupa por día y muestra los primeros 10 horarios libres del médico elegido, o de toda
  la especialidad si eligió "cualquier médico"; en ese caso cada horario dice con qué médico es
  (FR-16). "Ver más días" carga los 10 siguientes.
- Si ya tiene un turno futuro de esa especialidad, el paso 1 lo dice ahí mismo y no deja seguir:
  "Ya tenés un turno de Cardiología el martes 10. Para sacar otro, cancelá ese primero." (R-04)
- Si el horario se ocupó mientras confirmaba (RU-08): vuelve al paso 3 con el aviso
  "Ese horario se acaba de ocupar. Elegí otro." y la lista actualizada.
- Al confirmar: pantalla de éxito con el resumen y "Te mandamos el turno por email".
- El paciente puede elegir el médico o dejar que el sistema le ofrezca el primero libre (decisión del docente, S-28).

- El cursor arranca en el DNI. Enter busca; si el paciente no existe, se abre el alta en el
  mismo lugar con el DNI ya cargado (FR-02).
- Con flechas se recorre la lista de horarios; Enter da el turno. Es la única excepción al formato
  largo de fecha, porque la recepcionista lo lee al lado de la columna del día.
- Tras dar el turno: aviso verde "Turno dado: martes 10/11 14:30, Dr. Fernández" para dictarlo
  por teléfono, y el cursor vuelve al DNI para el siguiente paciente.
- Cancelar pide confirmación. La recepción no tiene el límite de 2 horas (FR-22).

### R2 · Agenda de un médico — FR-32, RU-06

Selector de médico y de día. Tabla: hora · paciente · DNI · estado. Los horarios libres se
muestran como "— libre —" para que se vea el hueco. Botón **Imprimir**.

**Hoja impresa (A4 vertical):** encabezado con hospital, médico, especialidad y fecha; tabla de
hora (en negrita, 14 pt), paciente y DNI. Sin colores: los cancelados se tachan. Pie con
fecha y hora de impresión y "Hoja X de Y".

### A4 · Usuarios del personal — FR-09, FR-10

Tabla de usuario, nombre, rol, médico vinculado (si es médico) y estado. Alta, desactivar y
reactivar. El alta genera una contraseña temporal que se muestra una sola vez y se cambia en el
primer ingreso. **[SUPUESTO S-30]**

### A5 · Auditoría — FR-34

Filtros: DNI, médico, rango de fechas, tipo de acción. Tabla de sólo lectura: fecha y hora,
quién, rol, canal, acción y detalle. Sin botones de edición ni borrado (FR-35).

## 8. Estados que toda pantalla contempla

| Estado | Qué se muestra |
|---|---|
| Cargando | Esqueleto gris del contenido, no una ruedita en pantalla vacía. |
| Vacío | Mensaje con la acción siguiente: "No hay horarios libres en los próximos 60 días. Probá con otra especialidad o llamá a la recepción." |
| Error de validación | Mensaje rojo debajo del campo, con lo que se espera: "El DNI tiene 7 u 8 números". |
| Error de regla de negocio | Cartel arriba del formulario, con qué pasó y qué hacer. |
| Error inesperado | "Algo falló. Probá de nuevo en unos minutos." Sin detalles técnicos (NFR-09). |
| Sesión vencida | Vuelve al ingreso y, después de entrar, a la pantalla donde estaba. |

## 9. Accesibilidad — NFR-05

- Todo se puede usar con teclado; el foco se ve siempre (borde de 3 px).
- Cada campo tiene etiqueta visible; nada de "placeholder como etiqueta".
- Los mensajes de error y de éxito se anuncian al lector de pantalla.
- El estado de un turno nunca depende sólo del color.
- La web del paciente funciona con zoom al 200 % sin scroll horizontal.
